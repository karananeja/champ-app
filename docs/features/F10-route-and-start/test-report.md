## 5. Verification findings
1. **Fixed: dialog buttons hidden by the keyboard on Android.** With edge-to-edge, Android doesn't resize the window for the keyboard, so the close and mark-faulty dialogs' buttons stayed underneath it. The dialogs now pad above the keyboard on both platforms (D-177, commit `c57e9b8`). Re-tested on the emulator.
2. **Typed routes:** `apps/mobile/.expo/types/router.d.ts` (git-ignored) is regenerated by Metro. After new routes are added, `pnpm typecheck` fails locally until Metro has run once. It passes on a fresh clone and after `pnpm --filter @champ/mobile start`.
3. **One dev-only console warning:** "Can't perform a React state update on a component that hasn't mounted yet" appeared once, on the first load after a cache-clearing Metro restart. It didn't recur on cold launches signed in or signed out. It has no user impact; to be watched in F10B.
4. **Not covered by the smoke test, so worth checking in UAT:**
   - iOS route rendering. Simulator taps can't be automated here; the iOS app was rebuilt and launches.
   - *Directions* opening the maps app.
   - Live GPS. The emulator's GPS override didn't apply, but the start position was recorded from the device.
   - The web assign-to-OE flow. It's covered by E2E.

## 6. Known limitations
- The fitment form, photos, scanning, Submit and the task summary come in F10B.
- `router.project-osrm.org` is a public demo server, for development only. Production needs a self-hosted OSRM, which is on the MVP backlog.
- The route isn't re-ordered while driving. That's deliberate (D-155): use *Recalculate route*.
- The order is enforced only against the stored route. A fitment added after the route was computed can start until the route refreshes (D-161).

## 7. UAT checklist (intent acceptance criteria)

**Before you start:**
- Run the API (`pnpm dev`, or `pnpm --filter @champ/api dev`) and Metro (`pnpm --filter @champ/mobile start`), then open Champ Dev.
- You need a technician with 3 or more fitments **for today** at different client sites (create the tasks on the web with today's fitment date and assign them).
- On the iOS Simulator, set the location with Features → Location → Custom Location.

| # | Acceptance criterion | Manual steps | Expected |
|---|---|---|---|
| 1 | Route on a map with a timeline | Open **Route** | Route line, numbered stops, timeline in the same order with "km · min from previous" |
| 2 | Starts from the current location; home when location is denied | Allow location, then deny it in settings and pull to refresh | "You" marker vs. the house marker with "Starting from your home location" |
| 3 | Only the next stop can be started | Open stop 2 | No *Start*; "After TK-…" on the timeline |
| 4 | Start needs location; start recorded | Deny location → *Start*; allow → *Start*; on the web open the task's History | Explanation dialog; then In progress, and the web history shows the start time and position |

| 6 | Continue placeholder | *Yes, continue* | "Fitment form coming soon"; status stays In progress |
